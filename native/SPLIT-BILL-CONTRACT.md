# Split Bill bundled integration — 2026-10-04

Scope: run the existing `feat/expense-first-ux` mini-app target in the root Swift/Kotlin hosts. Keep business/UI code in split-bill; preserve RN reference and all existing user edits. No website target, deployment, credentials, cloud auth, new public capabilities or policy relaxation.

Package: copy/rebuild source into temporary staging without writing either mini-app repo. Pin bundled manifest/assets with SHA-256 and check before creating a WebView. Trust is the host binary's bundled first-party package, not a signed external publication pipeline. A single native factory per platform serves `mini://split-bill` / `https://split-bill.miniapp.platform.local` with host CSP response header, own declared main-frame pages only, no direct egress, new windows, web persistence, file access or WebView media permission. No pool. Renderer death produces host recovery controls.

Protocol: existing shared-platform host bridge v1 `{id, capability, operation, version, args}`; host binds tenant/app/local-preview-user independently. Frozen capability snapshot before app script. Only manifest-declared, locally granted registry v1 storage.kv, scanner.scan, net.request. Canonical quota/payload rules come from generated policy. No raw native object/credential/path/image exposed. Unknown caller fields, version, operation, malformed/oversized requests and floods fail closed. Request IDs deduplicate side effects within the live session; audit metadata/digests precede terminal replies.

Storage: atomic host-private persistent JSON namespace per tenant/app/local-preview-user; bounded by registry payload cap. Success after durable write only; corrupt/full storage returns UNAVAILABLE and original bytes retained. Data is not backed up. Mini-app owns schema/value; close/restart retains committed draft. No server identity is implied.

Scanner: host-owned one-shot camera/photo picker, explicit per-call consent gesture; only bounded QR string returned. iOS system camera requires OS permission at use; photo picker does not require library access. Android system camera delegates capture with a temporary narrow URI grant, no host camera permission; picker uses a temporary read grant. Decode offline with Vision / ZXing core. Cancel/timeout/revoke/close drops result and releases image/temporary files. Manual QR input remains app fallback. No live streaming camera or generic camera API.

Network: only GET at declared `https://vietqr.net/api/banks`, no cookies/auth/cache or redirects; bounded response, finite deadline, cancel on background/close. App seed banks remain usable offline. Destination host is checked natively against manifest, path constrained by local integration grant.

Ownership: view/session owns bridge, pending operations, camera and timers. Background suspends requests and cancels network/scanner unless Android is completing its own system picker; returning resumes same view without rerender/reset. Close/tenant switch/destroy invalidate generation before cleanup. No callback can enter a new session. Process death restores only durable KV. System Back checks WebView history then host root close; native Close always works.

Acceptance: build both hosts; real WebView boot and draft read/write/reopen; malformed/forged/version/unknown/oversized/duplicate/flood tests, navigation/egress denial, decode fixture, denied/cancelled scanner, offline banks, background/close/late callbacks. Human: camera device, VoiceOver/TalkBack, large text/keyboard/orientation, deny/revoke and app-specific UX. Simulator/mock evidence does not prove device acceptance.

Budgets: canonical policy unchanged. Startup/warm open, per-WebView/host memory, FPS/crash rates, release binary growth and clean/incremental/reproducible build measurements require reference-device before/after; currently unverified. RN dependency/module/Pods/plugins counters unchanged; root Android adds one pure Java QR decoder, root build scripts add one staging sync tool (Mobile Platform owner; remove when signed package pipeline replaces bundled import). iOS uses system frameworks only. Rollback removes split-bill catalog registration, bundled assets and native view/adapters; retain KV for recovery.
